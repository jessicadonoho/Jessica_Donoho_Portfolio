03 · the problem

A critical tool that hadn't kept up with the team

The Trevor Project provides suicide prevention and crisis intervention for LGBTQ+ young people. Supervisors and monitors use the dashboard to assess risk levels and step in quickly. As the organization grew, five problems kept slowing them down:

Unnecessary data

Columns that were excessive, too long, or badly formatted created cognitive overload.

Missing Lifeline features

Lifeline users rarely opened the dashboard because it couldn't monitor live calls.

Night-shift eye strain

A bright interface made long overnight shifts physically uncomfortable.

Limited monitoring

Users could only watch 3 conversations at once but often needed to track 5 or more.

Low contrast

Several areas fell below WCAG contrast guidelines, making text hard to read.

04 · how we worked

The project workflow

The summer built on research from our January – May course project. I planned the work as five phases, each feeding the next, so the team always knew what it was working toward and what "done" meant before moving on.

  1. Discover

    Started from our course interviews and heuristic evaluation, then added interviews with users in Mexico.

  2. Define

    Synthesized findings, built personas, and prioritized problems into scope.

  3. Design

    Lo-fi and mid-fi wireframes, a design system, then a hi-fi prototype.

  4. Test

    Usability tests with dashboard users on the original platform and our redesign.

  5. Iterate

    Fixed issues from testing, surveyed participants, and prepared the handoff to development.

05 · research

Finding out what was really getting in the way

Our evidence came in two stages. In the January – May course project, our five-person team ran five interviews and a heuristic evaluation of the original dashboard. Over the summer we added about three interviews with users in Mexico. I set up and ran the research logistics (recruiting, scheduling, interview guides, synthesis) so we could move from questions to evidence quickly.

User interviews → 3 pain points

pain point 1

Unique workflows

Opportunity: let users customize and reorder columns so critical data is easy to reach.

pain point 2

Only three monitors at a time

Opportunity: redesign the "Monitoring Conversations" dock so users can track more conversations.

pain point 3

Night-shift eye strain

Opportunity: add a dark mode for low-light environments.

Heuristic evaluation → 3 top-severity findings

We evaluated the original dashboard against Nielsen's heuristics plus accessibility, and logged 10 findings. Three were rated most severe.

accessibility

Low color contrast

Recommendation: raise contrast and font weight to meet the WCAG 4.5:1 minimum.

flexibility & minimalist design

Redundant table data

Recommendation: remove overlapping columns like Source and Priority to make tables easier to scan.

recognition & real-world match

Unclear terminology

Recommendation: use plain-language labels, and add tooltips to abbreviations like CW and RS.

We turned interview findings into personas for the roles that rely on the dashboard most.

08 · design & build

A design system and eight new features

With the structure settled, we built a design system on The Trevor Project's official palette before moving to a hi-fi prototype: primary, secondary, and neutral color scales, Inter type in four roles, a shared icon set, and components with every state defined.

Feature 1 · Column customization

Users can add, remove, and reorder columns in an "Add Columns / Manage Column Order" modal, so critical data is always within reach.

Feature 2 · Expandable monitoring dock

The "Monitoring Conversations" dock expands so users can track several conversations side by side, with the dashboard still visible beside it.

Features 3 & 4 · Expandable details and notes

Expandable details keep extra case data out of the table until it's needed, and timestamped notes stay with the conversation, which makes transfers easier.

Feature 5 · Card view

Important overview data about counselors and available support is displayed in a way that lowers cognitive load, and its fields can be customized too.

Feature 6 · Dark mode

High-contrast text on dark grey reduces eye strain during long night shifts.

Feature 7 · Lifeline monitoring

Lifeline staff rarely opened the old dashboard because it couldn't monitor live calls. In the redesign, Lifeline conversations sit in the same table as Digital ones, with their own filter and monitoring control.

Feature 8 · Conversation search

A search box inside each monitored conversation finds keywords across the chat. It came directly out of usability testing, shown in the next section.

09 · test & iterate

Testing surfaced two more gaps

We ran five usability tests on the original dashboard and five on our redesign, iterating as we went. Testing the redesign turned up two issues we hadn't caught, and we fixed both before handoff.

Iteration 1 · Flexible message search

Users could only search chat logs with preset tags. We replaced the tags with a free-text search bar that covers the full message history.

Iteration 2 · Accordion button

The details section originally opened from the case number, but usability testing revealed that the case number is a hyperlinked pathway. We moved details to their own accordion button beside it.

11 · reflection

What I learned about running product work

lesson 1

Evidence makes scope easier

Tying every feature to an interview or heuristic finding made "what's in, what's out" conversations faster and less personal.

lesson 2

Research ops is product work

Getting participants scheduled early set the pace for the whole summer. When research slipped, everything slipped.

lesson 3

Test before you call it done

Two important gaps (chat search and how details open) only showed up in testing. Budgeting time to iterate paid off.

What I'd do differently

next step

Finish the plain-language work

A few findings from our evaluation of the original dashboard were still open at handoff: abbreviations like CW and RS, undo for closed chats, and cues for the active section. I'd pick these up next, starting with plain-language labels and tooltips.

next step

Test by role earlier

Rearranging columns, notes, and Lifeline monitoring were each named most helpful by one survey respondent and not valuable by another. Needs clearly vary, so I'd compare roles sooner to decide what belongs in the default view.

next step

Measure more directly

Our survey had three responses and asked people to predict the prototype's effect. Next time I'd gather more responses and add task-based measures, like how long it takes to find a conversation.
