03 · the problem

A critical tool that hadn't kept up with the team

The Trevor Project provides suicide prevention and crisis intervention for LGBTQ+ young people. Supervisors and monitors use the dashboard to assess risk levels and step in quickly. As the organization grew, five problems kept slowing them down:

Unnecessary data

Columns that were excessive, too long, or badly formatted created cognitive overload.

Missing Lifeline features

Lifeline users rarely opened the dashboard because it couldn't monitor live calls.

Night-shift eye strain

A bright interface made long overnight shifts physically uncomfortable.

Limited monitoring

Users could only watch 3 conversations at once but often needed to track 5 or more.

Low contrast

Several areas fell below WCAG contrast guidelines, making text hard to read.

04 · how we worked

The project workflow

I planned the summer as five phases. Each phase fed the next, so the team always knew what it was working toward and what "done" meant before moving on.

  1. Discover

    Moderated interviews and a heuristic evaluation of the current dashboard.

  2. Define

    Synthesized findings, built the persona, and prioritized problems into scope.

  3. Design

    Lo-fi and mid-fi wireframes, a design system, then a hi-fi prototype.

  4. Test

    Usability testing with dashboard users to find remaining friction.

  5. Iterate

    Fixed issues from testing, measured results, and prepared the handoff.

05 · research

Finding out what was really getting in the way

I set up and ran the research logistics (recruiting, scheduling, interview guides, synthesis) so we could move from questions to evidence quickly.

User interviews → 3 pain points

pain point 1

Unique worflows

Opportunity: let users customize and reorder columns so critical data is easy to reach.

pain point 2

Only three monitors at a time

Opportunity: redesign the "Monitoring Conversations" dock so users can track more conversations.

pain point 3

Night-shift eye strain

Opportunity: add a dark mode for low-light environments.

Heuristic evaluation → 2 critical issues

flexibility & efficiency

Lack of consistency/Real World Match

Fix: Create a clear design system with reliable button and tag appearance

consistency & standards

Contrast below 4.5:1

Fix: raise contrast and font weight to meet WCAG.

Who we were designing for

We turned interview findings into personas for the roles that rely on the dashboard most.

principal crisis worker

Kim Gómez · 29 · they/them

Kim monitors live crisis conversations across digital platforms and steps in when a counselor needs support. With 7 years of experience, they often support several people at once, but the dashboard's layout keeps them from seeing information and monitoring conversations effectively.

"I wish I could customize the dashboard. Everybody wants to see the information in a slightly different order."

Goals

  • Transfer chats so counselors can take breaks
  • Monitor chats for requests and address them

Needs

  • Rearrange columns to find specific information
  • Notifications when a conversation is updated

Frustrations

  • Too much time scrolling to find information
  • Losing track while monitoring multiple conversations
team lead

Alex Tran · 31 · she/her

Alex bounces between the supervisor dashboard and the workspace to watch active conversations and help counselors. During high-volume shifts, system resets and cluttered layouts make it hard to tell what needs attention.

"When the dashboard disappears during a reset, I have no idea if it's routine or a serious tech issue."

Goals

  • Prioritize urgent cases and triage support needs quickly
  • See Lifeline and Digital queues in one view

Needs

  • A warning and visible indicator when the system resets or has issues
  • Group and filter Lifeline and Digital sources together

Frustrations

  • No way to group Digital and Lifeline together
  • Resets wipe the dashboard with no warning, causing shift anxiety

Guardrails for the redesign

principle 1

Protect mental models

Keep the core framework so no one has to be retrained mid-crisis.

principle 3

Leave space for new features without breaking the layout.

07 · wireframes

From sketches to structure

We started with low-fidelity wireframes to agree on layout, then moved to mid-fidelity to test the structure and interactions before adding visual design.

08 · design & build

A design system and four features

With the structure settled, we built a design system on The Trevor Project's official palette before moving to a hi-fi prototype: primary, secondary, and neutral color scales, Inter type in four roles, a shared icon set, and components with every state defined.

Solution 1 · Dashboard customization

Users can add, remove, and reorder columns in an "Add Columns / Manage Column Order" modal, so critical data is always within reach.

Solution 2 · Expandable monitoring dock

The "Monitoring Conversations" dock expands so users can track several conversations side by side, with the dashboard still visible behind it.

Solution 3 · Details and Notes

Hidden data and notes feature are contained in an expandable accordion - allowing for ease of use when transferring conversations.

Solution 4 · Card Mode

Important overview data of counselors and available support are displayed in a way that allows for less cognitive load.

Solution 5 · Dark mode

High-contrast text on dark grey reduces eye strain during long night shifts.

09 · test & iterate

Testing surfaced two more gaps

Usability testing with dashboard users turned up two issues we hadn't caught. We fixed both before handoff.

Iteration 1 · Flexible message search

Users could only search chat logs with preset tags. We replaced the tags with a free-text search bar that covers the full message history.

Iteration 2 · Accordion Button

The details section was originally opened through the case number, usability testing revealed that the case number is a hyperlinked pathway.

11 · reflection

What I learned about running product work

lesson 1

Evidence makes scope easier

Tying every feature to an interview or heuristic finding made "what's in, what's out" conversations faster and less personal.

lesson 2

Research ops is product work

Getting participants scheduled early set the pace for the whole summer. When research slipped, everything slipped.

lesson 3

Test before you call it done

Two important gaps (search and note history) only showed up in testing. Budgeting time to iterate paid off.
